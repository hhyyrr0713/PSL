# PSL: Personal Styling Lab

PSL(Personal Styling Lab)은 Kaggle Fashion Product Images Dataset을 기반으로 상품 검색, 기준 아이템 선택, 상의·하의·아우터 후보 추천, 2피스·3피스 코디 추천까지 제공하는 개인화 패션 스타일링 추천 웹 서비스 프로토타입입니다.

이 프로젝트는 단순히 상품 목록을 보여주는 것이 아니라, 하나의 기준 상품을 중심으로 함께 입기 좋은 아이템을 탐색할 수 있도록 설계했습니다. 상품의 역할, 색상 조합, 무드, 핏, 계절감, 가격대, 이미지 정보를 추천 점수에 반영하고, 사용자가 마이페이지에 저장한 선호 브랜드, 색상, 무드, 핏, 가격대, 사용 상황을 추가 점수로 반영하여 개인화 추천 결과를 제공합니다.

또한 회원가입·로그인, 스타일 프로필 저장, 개인화 추천 ON/OFF, 단품 위시리스트, 마이페이지 조회 기능을 함께 구현하여 데이터 전처리부터 추천 로직, API 서버, 프론트엔드 UI, 사용자 데이터 저장까지 이어지는 end-to-end 추천 서비스 흐름을 구현하는 것을 목표로 했습니다.

> 본 프로젝트는 개인 포트폴리오 및 학습 목적으로 제작된 비상업적 프로토타입입니다.  
> 데이터는 Kaggle Fashion Product Images Dataset을 기반으로 하며, 실제 쇼핑몰 서비스 또는 특정 브랜드의 공식 서비스가 아닙니다.

## 1. 프로젝트 개요

PSL은 공개 패션 이미지 데이터셋을 서비스 형태의 추천 시스템으로 전환하는 과정을 직접 구현한 개인 프로젝트입니다. Kaggle 원본 데이터는 상품명, 색상, 카테고리, 시즌 등 기본 정보 중심으로 구성되어 있어 실제 추천 서비스에 필요한 브랜드, 가격, 재고, 핏, 무드, 세부 아이템 유형 정보가 부족했습니다. 이를 보완하기 위해 원본 데이터를 기존 스타일링 추천 엔진이 사용할 수 있는 스키마로 변환하고, 일부 속성은 규칙 기반으로 생성했습니다.

사용자는 웹 화면에서 상품을 검색한 뒤 기준 상품을 선택하고, 추천 브랜드·카테고리·가격대 필터와 개인화 반영 여부를 설정하여 다음과 같은 결과를 받을 수 있습니다.

- 상의 추천
- 하의 추천
- 아우터 추천
- 2피스 추천
- 3피스 추천

추천 결과는 단순 점수 목록이 아니라 상품 카드와 코디 카드 형태로 제공되며, 사용자는 마음에 드는 상품을 위시리스트에 저장하고 마이페이지에서 다시 확인할 수 있습니다.

1차 MVP에서는 추천 엔진이 웹에서 동작하는 것을 목표로 했고, 2차 MVP에서는 상품 이미지와 카드형 UI를 적용하여 실제 쇼핑 서비스처럼 탐색할 수 있는 화면으로 개선했습니다.

3차 MVP에서는 로그인, 마이페이지, 스타일 프로필, 개인화 추천 점수, 개인화 추천 ON/OFF, 단품 위시리스트 기능을 추가하여 비회원 추천 서비스에서 로그인 기반 개인화 추천 서비스로 확장했습니다.

이후 데이터 사용 범위와 공개 가능성을 고려하여 기존 특정 쇼핑몰 기반 데이터 구조를 제거하고, Kaggle 공개 데이터셋 기반 구조로 전환했습니다.

## 2. 사용 데이터셋 및 가상 브랜드

현재 데이터 및 추천 대상은 Kaggle Fashion Product Images Dataset을 기반으로 구성했습니다.

Kaggle 원본 데이터에는 실제 서비스용 브랜드, 판매가, 재고, 핏 정보가 충분히 포함되어 있지 않기 때문에 추천 기능 검증을 위해 일부 속성은 규칙 기반으로 가공했습니다.

현재 추천 화면에서 사용하는 가상 브랜드는 다음과 같습니다.

- MONO STUDIO
- URBAN LINE
- CLASSIC WORKS
- SOFT STANDARD
- MODERN ARCHIVE
- DAILY FORM

이 브랜드명은 실제 브랜드가 아니라, 추천 필터와 개인화 점수 기능을 시연하기 위해 생성한 가상 브랜드 값입니다.

## 3. 주요 기능

### 회원가입 / 로그인

3차 MVP에서 사용자 기반 기능을 추가했습니다.

구현 기능은 다음과 같습니다.

- 회원가입
- 로그인
- 로그인 성공 시 `localStorage`에 `user_id`, `username` 저장
- 메인 페이지 로그인 보호
- 마이페이지 로그인 보호
- 로그아웃
- 로그인 사용자명 표시

주요 페이지는 다음과 같습니다.

```text
/static/login.html
/static/register.html
/static/index.html
/static/mypage.html
```

### 스타일 프로필 저장

마이페이지에서 사용자의 선호 정보를 저장할 수 있습니다.

저장 항목은 다음과 같습니다.

- 선호 무드
- 선호 브랜드
- 선호 가격대
- 선호 핏
- 선호 색상
- 주 사용 상황

마이페이지 UI는 아코디언 구조로 구성했습니다.

```text
스타일 프로필 설정
 ├ 선호 무드
 ├ 선호 브랜드
 ├ 선호 가격대
 ├ 선호 핏
 ├ 선호 색상
 └ 주 사용 상황
```

색상은 color chip UI로 선택할 수 있도록 구성했고, 브랜드는 Kaggle 데이터에 맞춰 생성한 가상 브랜드 값을 기준으로 추천 점수에 반영했습니다.

### 상품 검색

사용자는 상품명, 가상 브랜드명, 상품 ID를 기준으로 상품을 검색할 수 있습니다.

검색 필터는 다음 조건을 지원합니다.

- 브랜드
- 역할: 상의 / 하의 / 아우터
- 카테고리
- 가격대

검색 결과는 카드 UI와 페이지네이션 방식으로 표시됩니다.

### 기준 상품 선택

검색 결과에서 상품 카드를 클릭하면 해당 상품이 추천의 기준 아이템으로 선택됩니다.

선택된 기준 상품은 이미지, 상품명, 가격, 브랜드, 역할, 카테고리, 시즌 정보와 함께 표시됩니다.

### 추천 조건 설정

추천 시 다음 조건을 설정할 수 있습니다.

- 추천 방식
  - 전체 보기
  - 상의 후보
  - 하의 후보
  - 아우터 후보
  - 2피스 추천
  - 3피스 추천
- 추천 브랜드
- 추천 카테고리
- 추천 가격대
- 동일 브랜드만 추천
- 개인화 추천 반영

### 개인화 추천

3차 MVP에서는 사용자가 저장한 스타일 프로필을 추천 점수에 반영했습니다.

개인화 점수 기준은 다음과 같습니다.

```text
선호 브랜드 +12
선호 가격대 +10
선호 색상 +8
선호 핏 +8
선호 무드 +15
주 사용 상황 +10
```

추천 결과에는 다음 값이 함께 포함됩니다.

```text
user_preference_score
personalized_score
personalized_reason
```

개인화 추천 반영 체크박스를 통해 개인화 적용 여부를 선택할 수 있습니다.

```text
체크됨: 개인화 추천 반영
체크 해제: 기본 추천 점수만 사용
```

### 2피스 / 3피스 개인화 반영

단품 후보뿐 아니라 2피스/3피스 코디 추천에도 개인화 점수가 반영되도록 확장했습니다.

세트 추천 결과에 상품별 브랜드, 색상, 핏, 무드, 가격대 정보를 붙이고, 기준 상품은 이미 사용자가 선택한 상품이므로 개인화 점수 계산에서 제외했습니다.

이를 통해 추천 세트 안의 하의나 아우터가 사용자의 선호 브랜드, 가격대, 색상 등에 맞는 경우 개인화 점수가 반영됩니다.

### 추천 결과 표시

추천 결과는 상품 카드 형태로 표시됩니다.

각 상품 카드에는 다음 정보가 포함됩니다.

- 상품 이미지
- 상품명
- 브랜드
- 판매가
- 역할
- 카테고리
- 시즌 정보
- 가격대
- 개인화 추천 이유

### 이미지 표시

Kaggle 상품 이미지 파일을 정적 파일 경로에 배치하고, 상품 카드와 코디 카드에서 이미지를 표시하도록 구현했습니다.

사용하는 이미지 컬럼은 다음과 같습니다.

- `image_url`
- `image_url_00`
- `image_url_01`
- `image_url_02`

Kaggle 데이터는 일반적으로 상품당 대표 이미지 1장을 사용하므로, 프론트엔드에서는 존재하는 이미지 URL만 배열로 구성하여 표시합니다.

### 2피스/3피스 코디 카드

2피스/3피스 추천 결과는 단순 표가 아니라 하나의 코디 카드처럼 표시됩니다.

코디 카드에는 다음 정보가 포함됩니다.

- 상의 이미지 / 상품명 / 가격
- 하의 이미지 / 상품명 / 가격
- 아우터 이미지 / 상품명 / 가격
- 세트 총 가격
- 추천 조합 설명
- 개인화 반영 점수

### 단품 위시리스트

3차 MVP에서 단품 위시리스트 기능을 추가했습니다.

상품 카드의 하트 아이콘을 클릭하면 상품을 위시리스트에 추가하거나 삭제할 수 있습니다.

구현 방식은 다음과 같습니다.

- 빈 하트 클릭: 위시리스트 추가
- 빨간 하트 클릭: 위시리스트 삭제
- 추가/삭제 결과는 토스트 메시지로 표시
- 마이페이지에서 단품 위시리스트 조회
- 마이페이지에서 위시리스트 상품 삭제

마이페이지 위시리스트는 첫 로딩 시 바로 호출하지 않고, 사용자가 위시리스트 영역을 펼쳤을 때 조회하도록 구성했습니다.

Kaggle 원본 데이터의 주요 컬럼은 다음과 같습니다.

- 상품 ID
- 상품명
- 성별
- 대분류
- 하위 분류
- 상품 유형
- 기본 색상
- 시즌
- 사용 상황
- 연도

추천 엔진이 사용할 수 있도록 다음과 같은 컬럼으로 변환했습니다.


```text
brand_name
sale_price
price_range
fit_type
has_stock
available_size_count
final_score
mood_*
age_*
season_*
top_subtype
bottom_subtype
sleeve_length_type
pants_length_type
```

현재 기준 데이터 파일은 다음과 같습니다.

```text
archive/styles.csv
```

상품 이미지는 정적 파일 경로에 배치하여 사용합니다.

```text
app/static/images/
```

## 7. 시즌 프로필 개선

초기에는 단순히 SS/FW 또는 계절 flag의 겹침 여부만 기준으로 계절감을 판단했습니다.

하지만 이 방식은 다음과 같은 문제가 있었습니다.

예를 들어, 여름+가을 아이템과 가을+겨울 아이템은 둘 다 “가을”이 겹치기 때문에 궁합이 좋다고 판단될 수 있습니다. 그러나 실제 체감 계절감은 여름축과 겨울축이 섞여 어색할 수 있습니다.

이를 개선하기 위해 시즌 정보를 다음 세 축으로 재해석했습니다.

- `season_warm_weight`
- `season_mid_weight`
- `season_cold_weight`
- `season_temperature_score`
- `season_profile_label`

즉 단순히 “계절이 겹치는가”가 아니라, 아이템의 체감 온도감이 얼마나 가까운지를 기준으로 계절 궁합을 판단하도록 개선했습니다.

3피스 추천에서는 상의, 하의, 아우터 전체 조합의 계절감 차이가 지나치게 벌어지지 않도록 coherence penalty를 추가했습니다.

## 8. 스타일링 추천 로직

추천 엔진은 규칙 기반 방식으로 구현했습니다.

사용 점수 요소는 다음과 같습니다.

- 무드 조화 점수
- 색상 조화 점수
- 포멀도 유사도
- 핏 조화 점수
- 브랜드 통일감
- 연령대 적합도
- 기존 상품 점수
- 역할 궁합 점수
- 시즌 궁합 점수
- 사용자 선호 점수

추천 방식은 크게 세 가지입니다.

### Pair 추천

기준 아이템과 다른 역할의 아이템 간 1:1 궁합을 계산합니다.

예시:

- 셔츠 기준 → 하의 추천
- 팬츠 기준 → 상의/아우터 추천
- 아우터 기준 → 상의/하의 추천

### 2피스 추천

기준 아이템을 포함하여 2개 아이템으로 구성된 조합을 추천합니다.

예시:

- 상의 + 하의
- 아우터 + 상의
- 하의 + 상의

### 3피스 추천

상의, 하의, 아우터를 포함한 3피스 코디 조합을 추천합니다.

3피스 추천에서는 pairwise 점수뿐 아니라 전체 조합의 계절감 coherence도 함께 고려합니다.

### 개인화 점수

사용자의 스타일 프로필과 추천 후보의 속성이 일치하면 기본 추천 점수에 사용자 선호 점수를 더합니다.

개인화 추천을 끄면 사용자 선호 점수는 0으로 처리되며, 기본 스타일링 추천 점수만 사용합니다.

## 15. 향후 개선 방향

### 4차 MVP: 추천 맥락 저장 및 위시리스트 고도화

현재 단품 위시리스트는 사용자가 저장한 상품을 확인할 수 있는 구조입니다.

다음 단계에서는 추천 상품이 어떤 기준 상품에서 파생되었는지 함께 저장하는 방향으로 확장할 계획입니다.

예상 개선 내용은 다음과 같습니다.

- 단품 위시리스트에 기준 상품 코드 저장
- 추천 출처 저장
  - 상의 후보
  - 하의 후보
  - 아우터 후보
- 마이페이지에서 기준 상품 → 저장 상품 관계 표시
- 단품 위시리스트 상세 페이지 구현
- 2피스/3피스 코디 위시리스트 구현
- 코디 상세 페이지 구현

이를 통해 사용자가 저장 상품을 다시 확인할 때, 단순히 상품만 보는 것이 아니라 “어떤 상품과 함께 입기 위해 저장했는지”까지 확인할 수 있도록 개선할 예정입니다.

### 추천 설명 개선

현재 추천 이유와 점수는 내부적으로 계산되며 일부 조합 설명에 활용됩니다.  
향후에는 사용자가 이해하기 쉬운 문장형 추천 설명을 더 정교하게 제공할 수 있습니다.

### 테마 기반 추천

비즈니스 캐주얼, 데일리, 미니멀, 포멀 등 사용자가 원하는 스타일 테마를 선택하면 해당 테마에 맞는 코디를 추천하도록 확장할 수 있습니다.

### 이미지 기반 코디 시각화

현재는 상품 이미지를 카드 형태로 나란히 보여주는 방식입니다.  
향후에는 상품 이미지를 조합하여 코디 시각화 기능으로 확장할 수 있습니다.

### 데이터 관리 구조 개선

현재 상품 데이터는 CSV 기반으로 로드하고, 사용자 정보와 위시리스트는 SQLite에 저장합니다.  
향후에는 PostgreSQL, MySQL 등의 DB를 연결하여 데이터 관리와 검색 성능을 개선할 수 있습니다.

### 배포

현재 앱은 로컬 환경에서 실행됩니다.  
향후 Render, Railway, AWS 등을 활용하여 외부 접속 가능한 형태로 배포할 수 있습니다.
